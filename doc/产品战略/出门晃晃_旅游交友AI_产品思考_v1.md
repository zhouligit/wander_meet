## 1. 文档目的

「旅游 + 交友 + AI」是投资人与用户都容易理解的三词组合，但若缺少产品边界，极易做成「什么都沾、什么都不深」。

本文档用于：

1. 厘清三者在出门晃晃中的**角色分工**；
2. 明确 AI **该做什么、不该做什么**；
3. 结合当前阶段（北京单城、月活偏低、活动主轴）给出**分阶段落地建议**；
4. 为后续 PRD / 融资话术提供统一口径。

---

## 2. 三个词各自解决什么

| 维度 | 用户真正要的 | 常见误做 |
|------|--------------|----------|
| **旅游** | 到陌生地方「有事做、有人一起、不踩坑」 | 做成 OTA 订票、攻略大全 |
| **交友** | 线下真实见面、弱压力社交、敢去 | 做成滑卡匹配、暧昧 dating |
| **AI** | 少决策、少踩坑、更快找到「今天能成的局」 | 做成聊天机器人陪聊、假人推荐 |

**出门晃晃已有答案（PRD v0.1）：**

> 旅游/同城场景 → 用「活动」当见面理由 → AI 辅助「发现与成局」，不替代「信任与人」。

与 NomadTable 公开叙事中「AI 推荐活动/地点」相近；出门晃晃更强调**微信生态、强审核、不做 1v1 私密匹配**。

---

## 3. 三角关系：产品架构图

```
┌─────────────────────────────────────────────────────────┐
│  出门晃晃核心（不要动）                                   │
│  活动组局 → 城市大群 → 线下见面 → 信任体系                 │
└───────────────────────────┬─────────────────────────────┘
                            │
        ┌───────────────────┼───────────────────┐
        ↓                   ↓                   ↓
   【旅游层】           【交友层】           【AI 层】
   换城/旅居/周末      同局弱连接          推荐今天能成的局
   地点/POI/路线       群聊协调            帮发局/写说明
                                           行程与活动对齐
                                           安全与内容审核
```

**关键结论：** AI 不应成为第三根主轴，而应挂在 **「提高成局率」** 与 **「降低运营/审核成本」** 上——对齐北极星指标 **24 小时成局率**。

## 4. AI 适合做什么、不适合做什么

### 4.1 适合（与现有产品兼容）

| 场景 | 做什么 | 价值 | 建议阶段 |
|------|--------|------|----------|
| **活动推荐** | 基于城市、距离、时间、标签、历史报名，推荐「今天/明天能报」的局 | 直接应对月活低、空窗率高 | P1 |
| **发局助手** | 帮组织者生成标题、简介、费用说明、注意事项（人可改） | 降低 KOC 发局门槛，补供给 | P1 |
| **地点/路线** | 搜地点增强、citywalk 粗路线、附近 POI 聚合成局建议 | 旅游感强，不抢活动主轴 | P2 |
| **行程对齐** | 「我这周在北京」→ 推荐可参加的活动时段（非 1v1 找人） | 服务旅居/出差人群 | P2 |
| **群聊摘要** | 活动群时间地点变更、待确认事项提炼 | 提高成局率，减少沟通摩擦 | P2 |
| **内容安全** | 敏感内容、引流、骚扰话术辅助审核 | 降本增效；与现有 content_security 衔接 | 现在可做 |
| **客服 / Onboarding** | 「第一次怎么用」「怎么选局」引导 | 提升注册→活跃转化 | P1 |

### 4.2 不适合（与 PRD、合规、品牌冲突）

| 场景 | 为什么不做 |
|------|------------|
| AI 匹配「灵魂伴侣/对象」 | dating 导向，审核与品牌风险 |
| AI 替用户私聊搭讪 | 虚假社交、骚扰放大 |
| AI 虚拟旅伴长期陪聊 | 留存假象，不导向线下成局 |
| 全自动发局无人审核 | 安全与供给质量失控 |
| 「AI 保证靠谱」 | 过度承诺，线下事故责任不清 |

## 5. 三条产品叙事（对内择一为主）

### 5.1 叙事 A：AI 活动助手（**最推荐，天使轮友好**）

> 不是 AI 帮你交友，是 **AI 帮你在北京今天找到能成的局**。

| 维度 | 说明 |
|------|------|
| 用户感知 | 首页「为你推荐」、发局页「一键生成说明」 |
| 投资人感知 | AI 提升成局率 / MAU，指标可验证 |
| 技术轻重 | 排序 + LLM 文案，不必先做复杂社交图谱 |

### 5.2 叙事 B：AI 旅居秘书（旅游感最强，偏中期）

> 你人在北京这周 → AI 根据空闲时段推荐活动 + 地点 + 交通提示。

| 维度 | 说明 |
|------|------|
| 适合人群 | 数字游民、出差、换城 |
| 风险 | 易做成「攻略 App」，分散运营火力 |
| 前提 | 北京供给稳定后再做，否则推荐也是空的 |

### 5.3 叙事 C：AI 信任增强（低调但长期有价值）

> AI 辅助审核、风险提示、异常行为识别；对用户只说「更安心」。

不 flashy，但与实名、照片验证、举报形成组合拳。

**建议：对外融资主讲 A，对内同时推进 C；B 等北京 MAU 起来再上。**

## 6. 与当前阶段（月活低、用户基本在北京）的结合

当前瓶颈是 **供给与回访**，不是「用户不知道 AI 是什么」。

**AI 落地优先级：**

```
1. 解决「首页没局可报」
   → 推荐现有局 + 运营种子局排期建议（运营侧工具）

2. 解决「发局太难」
   → 发局助手，拉 KOC 供给

3. 解决「来了不知道干嘛」
   → 新用户 3 个问题（周末/区内/咖啡 or 户外）→ 推荐列表

4. 再考虑行程、路线等「旅游+」功能
```

**反例：** 先做「AI 旅伴聊天」——月活可能略涨，成局率不变，融资时会被追问留存是否真实、AI 如何变现。

## 7. 商业模式：AI 放在哪

| 变现方式 | 是否自然 |
|----------|----------|
| 免费基础推荐 + 组织者「曝光加权」 | ✅ 与 Phase 1 工具费一致 |
| 出门晃晃+：更多推荐位、发局助手高级模板 | ✅ 与会员占位一致 |
| 向 B 端（咖啡、桌游、徒步俱乐部）卖「AI 组局/package 文案」 | ✅ 与 B 层供给一致 |
| 按 AI 聊天次数收费 | ❌ 偏离成局主轴 |
| AI 相亲/匹配 VIP | ❌ 与定位冲突 |

## 8. 融资话术建议

### 8.1 可以讲

> 出门晃晃是**高意图线下见面**平台；旅游/旅居是场景，交友是结果，**AI 是成局效率引擎**——帮用户在正确时间、正确地点，加入正确的活动。

### 8.2 避免讲

> 我们是 AI 驱动的旅游社交平台……（过虚，易被追问匹配、留存、合规）

### 8.3 一句对标

> NomadTable 用 AI 增强「发现活动与地点」；出门晃晃用 AI 增强「北京今天能成的局」，并叠加微信生态与信任体系。

## 9. 分阶段路线图

| 阶段 | 时间 | AI 能力 | 成功指标 |
|------|------|---------|----------|
| **0** | 现在 | 敏感内容审核辅助（与 content_security 衔接） | 审核效率 |
| **1** | 融资后 0–3 月 | 首页「今日推荐」规则 + 简单 LLM；发局文案助手 | 浏览→报名转化 ↑ |
| **2** | 3–6 月 | 新用户 onboarding 问答推荐；群聊时间地点摘要 | MAU ↑、7 日留存 ↑ |
| **3** | 6–12 月 | 行程时段对齐（「我这周在北京」）；citywalk 路线建议 | 成局率 ↑、组织者复发 ↑ |
| **不做** | — | 1v1 AI 匹配、AI 陪聊、虚拟好友 | — |

## 10. 三个战略取舍（建议拍板）

| # | 取舍 | 说明 |
|---|------|------|
| 1 | **AI 服务「活动」，不服务「找人」** | 推荐的是局，不是异性/搭子档案 |
| 2 | **AI 输出必须可审计** | 推荐可解释；发局文案人可改；活动仍过审核 |
| 3 | **旅游做「场景」，不做「业务」** | 不做订票订酒店；做「在某城这段时间参加什么局、去哪碰头」 |

## 12. 一句话总结

**旅游**提供「为什么在这里、想出门」的场景；**交友**是线下成局的结果，不是线上匹配产品；**AI**最适合当「成局加速器」——推荐局、帮发局、减空窗、辅审核——而不是第三个让人滑来滑去的主轴。

对出门晃晃现阶段，最顺的组合是：

> **北京活动社交 + AI 推荐/发局助手**  
> 而不是 **AI 旅游交友匹配平台**。
