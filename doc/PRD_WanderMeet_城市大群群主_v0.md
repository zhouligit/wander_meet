# WanderMeet 城市大群 · 群主制度（V0）

更新时间：2026-05-20  
状态：**已评审通过**（产品方案认可；按 P0→P3 迭代实现）  
关联：`doc/WanderMeet_城市大群_需求与接口规划.md`、`doc/WanderMeet_主播推广产品介绍_v1.md`、`doc/PRD_WanderMeet_裂变与信任_v1.md`

对标语境：NomadTable 类「城市桌 / 同城圈子」；城市大群为**平台官方群 + 任命制群主**，与活动群「发起人 = 群主」区分。

---

## 1. 背景与目标

### 1.1 现状

- 城市大群已上线：每 `cityCode` **一城一群**，技术载体为 `activity_kind=city_hall` 虚拟活动，复用报名与群聊。
- 当前 `organizer_id` 为内置 **「系统管理员」** 账号，用户侧**无真人群主**展示与治理能力。
- 产品文档二期曾规划「管理员、踢人/禁言」，尚未落地。

### 1.2 问题

- 大群成员增长后，缺少**本地人维护氛围**的抓手，广告与骚扰依赖平台事后处理。
- KOC / 主播 / 本地组织者有**带城意愿**，但无正式身份与权限，难以持续运营。
- 用户心智上，长期公共群需要可识别的**群主**，但不可照搬微信「谁建群谁说了算」。

### 1.3 目标

| 目标 | 说明 |
|------|------|
| **可运营** | 每城（有群主时）有明确负责人维护欢迎语、公告与明显广告处理 |
| **可 scale** | 全国百城可复制；冷启动靠任命，成熟期靠候选 + 审核 |
| **可控** | 群所有权归平台；群主权限有限；撤换与申诉机制完备 |
| **可导流** | 群主带动本城活动曝光与加群裂变，服务活动主线 |

**不在本期**：群主现金分成、用户自建 competing 城群、永久踢人/转让群。

## 2. 已拍板决策

| # | 决策点 | 结论 |
|---|--------|------|
| 1 | 群所有权 | **始终归旅聚平台**；`activities.organizer_id` 继续为系统账号，真人群主走独立 `city_group_hosts` 表 |
| 2 | 一群一主 | 每个 `cityCode` 官方大群 **最多 1 名群主** + **最多 2 名副群主** |
| 3 | 群主产生方式 | **任命 + 考核**，禁止「第一个进群当群主」「用户付费买群主」「纯投票」 |
| 4 | 对外称谓 | 用户可见 **「群主」**（资料页徽章同步）；系统字段 `host` / `deputy` |
| 5 | 私聊群主 | **大群/城群页不提供「私聊群主」**；仅「看资料」进公开主页，降低骚扰 |
| 6 | 群主空缺 | 群照常可用，展示「官方运营中」；满足条件时可开放「申请成为群主」 |
| 7 | 地理粒度 | 与现有城市大群目录一致（市 / 区县各一群各一主） |

## 3. 角色定义

### 3.1 三层治理

```
┌─────────────────────────────────────────┐
│  平台（所有权）  系统管理员 + 运营后台      │
├─────────────────────────────────────────┤
│  群主（运营权）  每城 1 人，任命制         │
├─────────────────────────────────────────┤
│  副群主（协助）  每城 0～2 人，群主提名+平台确认 │
└─────────────────────────────────────────┘
```

### 3.2 与活动群对比

| 维度 | 城市大群群主 | 活动群发起人 |
|------|--------------|--------------|
| 载体 | `city_hall` | `event` |
| 任期 | 长期，可撤换 | 随活动结束 |
| 任命 | 平台 / 审核 | 用户创建活动 |
| 展示 | 「群主 · XX 城」 | 「发起人」 |
| 核心职责 | 氛围、公告、轻治理、导流活动 | 组织单场局 |

## 4. 群主产生与生命周期

### 4.1 来源渠道（可并行）

1. **运营后台任命**：冷启动、重点城市、主播/KOC 合作签约。
2. **邀请申请**：运营或现任群主邀请达标用户，用户确认后进入审核。
3. **公开申请**（仅当该城同时满足：已有群主空缺 ≥ 30 天、大群成员 ≥ 100）：用户提交申请 → 运营审核。

### 4.2 准入门槛（须同时满足）

| 条件 | 规则 |
|------|------|
| 身份 | 已完成 **照片验证**；建议已有 **组织者认证** |
| 在场 | 资料或近 90 天行为表明 **与该 `cityCode` 同城**（发过/参加过该城活动，或大群发言） |
| 贡献 | 近 60 天：**大群有效发言 ≥ 10 条** 或 **成功组局 ≥ 1 场**（该城 `event`） |
| 信任 | 账号 `active`；无未处理严重举报；无禁言/封禁记录 |
| 承诺 | 勾选《城市群主公约》 |

### 4.3 城市成熟度分级

| 级别 | 成员规模 | 群主策略 |
|------|----------|----------|
| **L0 空城** | 0～49 | 仅运营任命种子/KOC；不开放用户申请 |
| **L1 萌芽** | 50～199 | 任命 + 邀请申请 |
| **L2 活跃** | 200+ | 开放申请入口 + 候选池推荐 + 副群主 |

### 4.4 考核与撤换

| 触发 | 动作 |
|------|------|
| **30 天无登录** 且未委托副群主 | 系统警告 → 7 天后自动降为空缺，副群主顺位顶替（若有） |
| **7 天内 ≥ 3 次有效举报属实**（群主滥权） | 平台暂停权限 → 调查 → 撤换 |
| 违反《城市群主公约》（导流、骚扰、卖课等） | 立即撤换，必要时封号 |
| 群主主动辞职 | 空缺；副群主可申请转正（运营审核） |
| 城市合并 / 目录调整 | 运营手动迁移或重新任命 |

## 5. 权限矩阵

### 5.1 群主 / 副群主

| 能力 | 群主 | 副群主 | 频控 |
|------|:----:|:------:|------|
| 编辑群简介、欢迎语模板 | ✅ | ✅ | 变更走敏感词审核 |
| 发布 / 更新群公告 | ✅ | ✅ | 3 条 / 周 |
| 群内置顶消息 | ✅ | ✅ | 1 条 / 周 |
| 推荐本城活动卡片进群 | ✅ | ✅ | 5 条 / 周 |
| 删除明显广告消息 | ✅ | ✅ | 日志审计 |
| 禁言 24h | ✅ | ✅ | 同一用户 7 天内最多 1 次；超限走举报 |
| 提名副群主 | ✅ | ❌ | 每城最多 2 副群主 |
| 查看群主数据看板 | ✅ | 只读 | P3 |

### 5.2 明确禁止（群主 / 副群主均不可）

- 解散群、转让群、设私密、改 `cityCode` 绑定
- 永久踢人、永久禁言
- 查看成员手机号、批量私信营销
- 未经审核的外链、付费推广、婚恋/培训/微商导流

### 5.3 平台保留

- 任命 / 撤换群主与副群主
- 封号、全群禁言、删除任意消息
- 系统消息（群规、安全提示、新人欢迎兜底）
- 申诉复核与 audit log

## 6. 用户体验

### 6.1 城市大群详情页（`city-hall` 单城）

**有群主时：**

```
上海 · 同城大群
旅聚官方 · 1,248 人在聊

┌──────────────────────────────┐
│ [头像]  群主 · 小林              │
│         上海组局 12 场 · 已验证    │
│         [看资料]                 │
└──────────────────────────────┘

📌 群公告
欢迎来上海的朋友！进群可先自我介绍…

[ 加入大群 ] / [ 进入大群 ]
```

**无群主时：**

- 副标题：`旅聚官方 · 友善交流，违规可举报`
- 不展示群主卡片；成员 ≥ 100 且空缺 ≥ 30 天时展示「申请成为群主」（链到申请页，P2）。

### 6.2 群聊内

- 群主 / 副群主消息旁展示小标签 **「群主」** / **「管理」**（低调样式，与活动群区分）。
- 新人进群：系统消息发送欢迎语（群主模板优先，无模板则用平台默认）。
- 长按消息：普通用户 → 举报；群主/副群主 → 额外「删除」「禁言 24h」（P1）。

### 6.3 用户公开资料页

- 徽章：**「XX 城群主」** 或 **「XX 城副群主」**（`cityName` 取自 `cityCode` 解析）。
- 不在大群顶部提供「私聊群主」按钮。

### 6.4 消息 Tab 会话列表

- 城市大群会话保持现有「城市大群」标签；不在列表项展示群主名（避免信息过载）。

## 7. 激励与义务

### 7.1 激励（非现金起步）

| 类型 | 内容 | 阶段 |
|------|------|------|
| 身份 | 资料页徽章、大群详情展示 | P0 |
| 曝光 | 本城活动列表「群主推荐」位（每周 1 槽） | P2 |
| 裂变 | 专属邀请海报 / 小程序码统计加群 | P3 |
| 数据 | 群主看板：新进、活跃、活动转化 | P3 |
| 进阶 | 「城市合伙人」线下补贴等 | 再议 |

### 7.2 《城市群主公约》要点

- 24h 内处理群内明显广告与骚扰引战（否则平台介入）。
- 不得利用群主身份从事商业导流、婚恋承诺、培训卖课。
- 每周至少登录维护 2 次，或明确委托副群主。
- 接受平台审计与撤换规则。

## 8. 风控与合规

- 所有群主/副群主删消息、禁言操作写入 **`admin_audit_logs`**（或专用 `city_group_host_actions`）。
- 被禁言用户：**一键申诉** → 平台 48h 内复核（P1）。
- 群主发的公告 / 简介：**复用现有文本内容安全**（与聊天 `SEC_SCENE.SOCIAL` 一致）。
- 与现有 **举报**（`targetType` 扩展 `city_hall_message` / `city_group_host`）、**照片验证**、**组织者认证** 打通。
- 参考裂变 PRD：城市大群**不做见面互评**，避免大群场景滥用。

## 10. 后端设计（`wander_meet`）

### 10.1 数据模型

**新表 `city_group_hosts`**

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT PK | |
| city_code | VARCHAR(32) | 与 `activities.city_hall_city_code` 一致，**UNIQUE**（每城一行主记录扩展用 role 区分） |
| user_id | BIGINT FK → users | |
| role | VARCHAR(16) | `owner` \| `deputy` |
| status | VARCHAR(16) | `active` \| `suspended` \| `resigned` |
| appointed_by | BIGINT NULL | 运营 user_id 或 NULL（系统） |
| appointed_at | DATETIME | |
| resigned_at | DATETIME NULL | |
| welcome_text | VARCHAR(500) NULL | 欢迎语模板 |
| announcement | VARCHAR(1000) NULL | 当前公告 |
| announcement_updated_at | DATETIME NULL | 频控 |
| meta_json | JSON NULL | 扩展：邀请码、统计快照等 |

**约束**

- `(city_code, role='owner')` 最多 1 条 `active`。
- `(city_code, role='deputy')` 最多 2 条 `active`。
- **不修改** `activities.organizer_id`（仍为系统管理员）。

**可选 P1：`city_group_host_actions`**

| 字段 | 说明 |
|------|------|
| host_id, action, target_message_id, target_user_id, created_at | 删消息、禁言等审计 |

**可选 P2：`city_group_host_applications`**

| 字段 | 说明 |
|------|------|
| city_code, user_id, status, reviewer_admin_id, created_at | 申请与审核 |

### 10.2 API 变更（camelCase 响应）

#### 改造现有

| 方法 | 路径 | 变更 |
|------|------|------|
| GET | `/city-groups/lookup` | 增加 `owner: { userId, nickname, avatarUrl, role } \| null` |
| GET | `/city-groups/catalog` | 每 city 可选带 `ownerNickname`（列表简略） |

#### 新增 — 公开读

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/city-groups/by-city-code/{cityCode}/profile` | 群资料：简介、公告、owner、deputies、memberCount |

#### 新增 — 群主写（P1，须 `owner`/`deputy` + 限频）

| 方法 | 路径 | 说明 |
|------|------|------|
| PATCH | `/city-groups/me/host-profile` | 更新 welcomeText、announcement（body: `cityCode`） |
| POST | `/city-groups/me/recommend-activity` | 活动卡片进群（body: `cityCode`, `activityId`） |
| POST | `/city-groups/me/messages/{messageId}/delete` | 删消息 |
| POST | `/city-groups/me/members/{userId}/mute` | 禁言 24h |

#### 新增 — 运营 Admin

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/admin/city-group-hosts` | 列表 ?cityCode&status |
| POST | `/admin/city-group-hosts` | 任命 owner/deputy |
| PATCH | `/admin/city-group-hosts/{id}` | 暂停 / 撤换 |
| GET | `/admin/city-group-host-applications` | 申请队列（P2） |
| POST | `/admin/city-group-host-applications/{id}/approve` | 通过并任命 |

#### 权限校验要点

- 写操作校验：`city_group_hosts` 中 `user_id = current_user` 且 `status=active`。
- 禁言 / 删消息：校验目标消息属于该城 `city_hall` 对应 `activity_id`。
- 城市大群消息接口仍走现有 `/activities/{activityId}/messages`；P1 可在 service 层增加群主分支。

### 10.3 Schema 扩展示例

```python

    role: str  # owner | deputy
```

## 12. 运营 SOP（P0 冷启动）

1. 选定 5～10 城及种子群主（本地 KOC / 已认证组织者 / 合作主播）。
2. 后台创建 `city_group_hosts`（`role=owner`）。
3. 协助群主撰写欢迎语与首条公告；必要时代发首周置顶。
4. 监控举报与活跃；30 天复盘是否需撤换或增补副群主。
