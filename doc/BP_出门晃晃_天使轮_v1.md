## 一页摘要（Executive Summary）

**一句话：** 出门晃晃是面向独行出行者与同城独居青年的**高意图线下见面平台**——用「城市大群 + 小活动组局」让用户**今天就能找到人，一起做点事**。

**我们在做什么：** 微信小程序。用户先加入北京等城市大群建立弱连接，再报名咖啡局、 citywalk、徒步等小型线下活动；平台提供认证发局、群聊协调、信任与安全机制，终点是**真实见面**，不是无限滑卡匹配。

**为什么现在：** 独居与流动人群扩大，线下轻社交需求明确；微信群碎片化、活动平台缺信任层；海外 NomadTable 等已验证「活动组局」品类，中国市场仍缺微信原生、强信任、可运营复制的方案。

**牵引力（截至 2026-07）：** 累计注册 **400+**，**月活（MAU）尚处早期、占注册比例较低**；用户 **基本均为北京**，与单城验证策略一致；产品已跑通注册 → 加群 → 发局/报局 → 群聊 → 分享裂变全链路。

**融资需求：** 寻求天使轮 **人民币 500 万元**（可谈），用于北京单城模型验证、核心团队扩充与城市运营，目标 **12 个月内**跑通可复制的「供给—成局—留存」单位模型，为 Pre-A 融资准备数据与叙事。

**核心指标（北极星）：** **24 小时成局率**——活动发布后 24 小时内达到最小成团人数并实际发生线下见面。

## 1. 问题与机会

### 1.1 用户痛点（场景化）

| 人群 | 典型场景 | 现有方案的问题 |
|------|----------|----------------|
| 独行旅行者 / 数字游民 | 刚到陌生城市，想快速找到同路人 | 微信群分散、信息噪声大、难以判断靠谱程度 |
| 同城独居青年 | 周末想出门社交，朋友圈凑不齐人 | 泛社交 App 意图模糊、匹配链条长、线下转化率低 |
| 出差 / 换城上班族 | 短驻某城，希望有「今天能参加的事」 | 大众点评/小红书偏内容，缺少「报名—成团—见面」闭环 |
| 活动组织者（KOC） | 想组小局但缺工具和信任背书 | 私域群运营成本高，缺乏平台曝光与风控支持 |

**共性：** 用户需要的不是「更多聊天对象」，而是**可执行的线下见面理由**和**可信的同行者**。

### 1.2 市场机会（北京切入口）

我们不主张「全中国 3 亿独居 = TAM」的粗放叙事，而采用**可验证的切入口**：

| 层级 | 定义 | 估算逻辑（保守） |
|------|------|------------------|
| **TAM** | 中国一线/新一线高意图线下轻社交需求人群 | 数千万级（旅居、独居、流动办公等叠加） |
| **SAM** | 北京 18–45 岁、有微信、周末/工作日愿意参加 2–4 小时线下小局 | 约 **300–500 万** 潜在人群 |
| **SOM（12–18 个月）** | 北京可触达并转化的种子用户 | 注册 **8,000–1.5 万**；月活 **2,000–4,000**；月活跃组织者/参与者 **200–400** |

**品类验证：** 海外 NomadTable 等产品以「旅人线下组局 + 城市圈子」获得用户与订阅收入，说明**活动主轴的见面社交**是成立品类；出门晃晃的差异在于**微信生态、城市大群结构、发局认证与强风控**。

### 1.3 为什么不是 dating、不是泛社交

- **意图更清晰：** 活动主题（咖啡、徒步、展览）天然降低骚扰与误解风险  
- **更易 monetize：** 组织者工具费、活动服务费、会员权益均可围绕「成局」设计  
- **合规更可控：** 不做 1v1 私密匹配、不做 dating 导向话术，符合小程序审核与品牌安全

## 2. 产品与解决方案

### 2.1 产品定位

| 维度 | 说明 |
|------|------|
| **是什么** | 同城**高意图线下见面**平台：城市大群 + 线下活动组局 |
| **不是什么** | 不是 dating App、不是无限滑卡交友、不是纯内容社区 |
| **核心承诺** | **今天就能找到人，一起做点事** |
| **主端** | 微信小程序「出门晃晃」 |

### 2.2 双主线产品飞轮

```
┌─────────────────────────────────────────────────────────┐
│  城市大群（低门槛）                                       │
│  选城 → 加入北京大群 → 弱连接、拼饭、找搭子、发定位       │
└───────────────────────────┬─────────────────────────────┘
                            ↓ 自然转化
┌─────────────────────────────────────────────────────────┐
│  线下活动（高意图）                                       │
│  浏览/搜地点 → 报名 → 活动群聊 → 线下见面                 │
└───────────────────────────┬─────────────────────────────┘
                            ↓ 闭环
┌─────────────────────────────────────────────────────────┐
│  信任与留存                                               │
│  认证发局 · 照片验证 · 见面打卡 · 互评 · 举报/拉黑        │
└─────────────────────────────────────────────────────────┘
```

**逻辑：** 大群解决「我在北京，先有个同城入口」；活动解决「我今天想出门，立刻有局可报」；信任层解决「敢不敢去」。

### 2.3 已实现核心能力（MVP+）

| 模块 | 能力 | 用户价值 |
|------|------|----------|
| 账号 | 手机号登录、资料、新手引导 | 低门槛进入 |
| 城市大群 | 全国城群目录，按省/市/区县加入 | 换城不从零社交 |
| 活动 | 发布/浏览/报名/取消；分类、搜地点、分享码 | 成局主链路 |
| 群聊 | 活动群、城市大群；文本/图片/表情/定位 | 见面前对齐 |
| 信任 | 发活动需认证；照片验证；举报/拉黑/封禁 | 降低线下风险感知 |
| 实名报名 | 组织者可选开启（姓名+身份证，供保险等场景） | B 端/合规场景扩展 |
| 同城动态 | 同城/关注流、点赞评论 | 提升留存与弱连接 |
| 增长 | 邀请归因、活动分享小程序码 | 可追踪裂变 |
| 支付（预埋） | 发布活动付费、后续报名费接口预留 | 商业化基础设施 |

**技术：** 统一 FastAPI 后端 + MySQL + Redis；生产环境已部署（阿里云/百度云）；接口与小程序联调完成。

### 2.4 北极星与一级指标

| 类型 | 指标 | 定义 |
|------|------|------|
| **北极星** | 24 小时成局率 | 活动发布后 24h 内达到最小成团人数且实际线下发生 |
| 一级 | 活动发布数/周 | 北京有效供给 |
| 一级 | 浏览→报名转化率 | 需求匹配效率 |
| 一级 | 到场率 | 避免「假繁荣」 |
| 一级 | 7 日留存 | 用户是否回来 |
| 一级 | 组织者复发率 | 供给能否自循环 |
| 预警 | 活动流空窗率 | 首页是否「今天有局可报」 |
| 预警 | 安全举报率 | 风控与品牌风险 |

## 3. 商业模式

### 3.1 收入路径（分阶段，避免「只有会员」）

| 阶段 | 时间 | 收入来源 | 说明 |
|------|------|----------|------|
| **Phase 1** | 0–12 月 | 组织者工具费 | 发布活动/曝光加权（技术已实现，可按城灰度开启） |
| **Phase 1** | 0–12 月 | B 端场地共创 | 咖啡、桌游、户外门店联合发局，后期 CPS/赞助 |
| **Phase 2** | 12–24 月 | 活动报名费抽成 | 定金/全价平台托管（需微信官方支付、退款与客诉体系） |
| **Phase 2** | 12–24 月 | 出门晃晃+ 会员 | 置顶、认证标识、数据洞察（占位已预留，不对 C 端 dating 售卖） |

**原则：** 近期以**轻量、可试、低合规成本**的收入为主；活动代收需等北京单城模型与支付牌照就绪后再规模化。

### 3.2 单位经济（目标方向，非当前事实）

天使轮阶段重点验证**供给侧与成局率**，以下为 **12 个月目标方向**（融资后需用真实数据替换）：

| 指标 | 目标区间（北京） |
|------|------------------|
| 有效组织者（月发 ≥1 局） | 50–100 人 |
| 月成局数（达到最小成团且发生） | 80–200 局 |
| 单局平台收入（Phase 1 工具费均摊） | ¥5–20 |
| 月 ARPU（活跃参与者） | ¥2–8（Phase 1 以 B 端与工具费为主） |

## 4. 牵引力与现状

### 4.1 核心用户数据（真实口径）

| 指标 | 当前状态 | 说明 |
|------|----------|------|
| 累计注册 | **400+** | 完成手机号登录 |
| 月活（MAU） | **较低** | 注册→活跃转化尚未建立；尽调可提供分月明细 |
| 地域分布 | **基本均为北京用户** | 与 PRD「北京首站」一致，未分散运营火力 |
| 产品链路 | 已闭环 | 注册、加群、发局/报局、群聊、分享均可完成 |

**注册 / 月活比（定性）：** 典型早期「有种子用户、缺持续供给与运营」形态——用户来了，但**首页常缺「今天能报的局」**，导致回访不足。这正是天使轮资金要解决的**运营问题**，而非产品不可用。

### 4.2 已有进展

| 项 | 状态 |
|----|------|
| 产品 | 微信小程序「出门晃晃」已上线，核心链路可闭环 |
| 用户 | 注册 400+；北京集中度极高，适合单城叙事 |
| 城市 | 产品能力支持全国城群；**实际用户与运营均聚焦北京** |
| 后端 | 生产 API 稳定运行；活动、群聊、认证、分享码等已落地 |
| 合规 | 软著材料筹备中；小程序审核经验积累；安全提示与举报体系已嵌入 |
| 对标 | 产品体验参考 NomadTable，执行路径适配微信生态与中国风控 |

### 4.3 当前阶段判断（诚实表述）

我们处于 **「有产品 + 有种子用户 → 证明活跃与成局」** 阶段：

- **已证明：** 北京用户愿意注册并完成加群/报局；产品与技术可支撑快速迭代；用户地域高度集中，**没有虚假的多城繁荣**  
- **尚未证明：** 稳定月活、24h 成局率、组织者自循环、7 日留存  
- **月活低的主要原因（我们判断）：** ① 北京有效活动供给不足，空窗期多；② 运营人力有限，未系统跑 KOC/种子局；③ 裂变与渠道尚未规模化投放  

**对投资人的含义：** 天使轮买的是**团队 + 品类判断 + 北京种子 + 单城跑通路径**；资金主要投向**供给与运营**，把「400 注册」转化为「可复用的月活与成局模型」，而不是买入当前活跃度。

### 4.4 北京用户集中 — 是约束也是优势

| 维度 | 解读 |
|------|------|
| 对融资叙事 | 与 BP「北京单城验证」完全一致，数据干净、可复制路径清晰 |
| 对产品 | 城群、活动、搜地点均围绕北京调优，无需为多城分散迭代 |
| 对风险 | 需警惕「只有注册、没有回访」；融资后首要是 **MAU 与成局**，不是再铺更多城市 |

### 4.5 北京冷启动计划（S/A/B 供给模型）

| 层级 | 策略 | 目标 |
|------|------|------|
| **S 官方种子** | 团队/运营每日 5–10 场模板局（咖啡、 citywalk、夜跑、桌游） | 保证首页「今天可参加」 |
| **A KOC 组织者** | 招募 30–50 位认证组织者，每人每周 ≥2 局 | 供给自循环 |
| **B 商家共创** | 10–20 家场地联合发局（初期不收费，换曝光） | 降低组织成本、丰富场景 |

**渠道：** 短视频/主播合作（已有对外介绍稿）、城市大群自然传播、邀请裂变（有效行为计奖，非纯注册）、活动分享小程序码。

## 5. 竞争与壁垒

### 5.1 竞争格局

| 类型 | 代表 | 与出门晃晃的差异 |
|------|------|------------------|
| 微信群 / 私域 | 各类同城群 | 分散、无结构化活动与信任层 |
| 泛社交 / dating | 陌陌、Soul 等 | 意图模糊、线下成局链长、合规风险高 |
| 活动平台 | 部分组局小程序 | 常缺城群弱连接、缺认证与风控深度 |
| 内容社区 | 小红书 | 种草强、报名—成团—见面闭环弱 |
| 海外对标 | NomadTable | 品类验证；我们走微信原生 + 中国信任运营 |

### 5.2 可构建的壁垒

1. **信任体系：** 认证发局 + 照片验证 + 举报封禁 + 实名报名（非人人必填，高意图场景启用）  
2. **双主线结构：** 城群降低获客成本，活动提高成局效率——结构难用纯列表复制  
3. **数据飞轮：** 见面打卡、互评、信任分 → 曝光加权 → 组织者留存（设计已完成，待规模验证）  
4. **北京运营 know-how：** 种子局模板、KOC 网络、场地合作——单城深度可复制到其他城市

## 6. 市场进入策略（北京 12 个月）

### 6.1 里程碑

| 时间 | 目标 | 关键结果 |
|------|------|----------|
| M1–M3 | 供给稳定 | 北京首页空窗率 <20%；周发布活动 ≥30 场；**MAU 较基线提升 2–3 倍** |
| M4–M6 | 成局验证 | 24h 成局率 ≥40%（官方+KOC 局）；月成局 ≥60 局；**MAU ≥800** |
| M7–M9 | 留存与裂变 | 7 日留存 ≥25%；有效邀请占比 ≥40%；**MAU ≥2,000** |
| M10–M12 | 模型总结 | 可复制 playbook；北京累计注册 **8,000+**；**MAU ≥3,000**；准备 Pre-A 数据包 |

### 6.2 关键运营动作

- 聚焦 **4 类模板局**：下班咖啡、周末 citywalk、夜跑、桌游（PRD 已验证方向）  
- 优先区域：**朝阳 / 海淀 / 东城 / 西城**（地铁口、商场、连锁咖啡等公共场所）  
- 安全前置：详情页/报名页固定安全提示；不鼓励私下大额转账  
- 数据看板：按周复盘北极星及空窗率、举报率

## 9. 风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 月活偏低、回访不足 | 投资人质疑增长 | 优先补北京供给（S/A/B）；以成局带动回访；周度跟踪 MAU/注册比 |

### 12.2 核心数据定义（便于尽调对齐）

- **注册用户：** 完成手机号登录的用户数（当前 **400+**，**基本均为北京**）  
- **月活（MAU）：** 自然月内至少有一次有效行为（打开小程序并完成浏览/加群/报局/发消息等）的去重用户数；**当前处于早期、占注册比例较低**，尽调可提供月度明细  
- **成局：** 活动达到组织者设定最小人数且至少 2 人在线下发生见面（以打卡/组织者确认计，规则需在运营手册中固化）  
- **24h 成局率：** 上述成局数 / 同期发布且开放报名的活动数  
- **MAU/注册比：** 衡量「种子是否转化为活跃」；融资后 12 个月目标 **≥30%**
