# 旅聚 WanderMeet — 首页搜地点（PRD v0.1）

> **状态**：已评审（产品确认按本版实施）  
> **范围**：仅首页活动流；不影响发现页、发布页、城市大群等  
> **关联**：`Tech_WanderMeet_首页搜地点_v0.1.md`（前后端技术方案）、`PRD_WanderMeet_v0.1_Beijing.md` §6.2

---

## 1. 背景与目标

### 1.1 背景

首页副标题为「{城市} · 今天就能找到人」，活动列表默认以 **GPS 授权定位** 解析出的 `cityCode` + `lat/lng` 拉取（今天 / 明天 / 距离优先 / 全部）。用户常希望先看 **「我要去的那片区域」** 附近的活动，而不是刚打开小程序时的物理位置。

发现页已有「搜地点找活动」（文字联想 + 独立列表页 `place-activities`），交互与首页诉求不同；发布页已有地图 + POI 选点（`location-picker`）。

### 1.2 目标

在首页增加 **地图/POI 式搜地点** 入口；用户选定地点后，首页列表的 **城市范围** 与 **距离计算基准** 均改为 **所选地点**，直至用户清除或恢复「使用当前定位」。

### 1.3 非目标（v0.1 不做）

- 不改发现页 `place-activities`、发布页选点逻辑。
- 不把首页搜索锚点写入全局 `HOME_*` GPS 缓存（避免污染其它逻辑）。
- 不新增后端「地点搜索」接口（POI 仍走高德 Web，与发布选点一致）。
- 不做搜索历史、热门城市榜单（可 v0.2）。

## 2. 用户故事

| 角色 | 故事 | 验收 |
|------|------|------|
| 参与者 | 我计划周末去枣庄，想在首页先看枣庄附近「今天/明天」的活动 | 搜「枣庄」或具体 POI 后，列表与副标题反映该地 |
| 参与者 | 我想看国贸附近 5km 内按距离排序的活动 | 选 POI 后切「距离优先」，距离相对搜索点 |
| 参与者 | 我搜错了，想回到真实定位 | 点「使用当前定位」后恢复 GPS 锚点并刷新列表 |

## 3. 信息架构与排版（已确认）

### 3.1 入口位置

在首页 **头部区域**（品牌行与筛选 chips 之间），增加一行 **搜索入口**：

```text
+--------------------------------------------------+
| 旅聚                                              |
| 枣庄 · 今天就能找到人          （副标题，见 3.3）   |
+--------------------------------------------------+
| [🔍 搜索地点：国贸 / 点击选择]     （新增）        |
+--------------------------------------------------+
| [今天] [明天] [距离优先] [全部]                   |
+--------------------------------------------------+
| 活动卡片列表…                                     |
+--------------------------------------------------+
```

- 未搜索：占位文案如「搜索地点，查看附近活动」。
- 已搜索：展示 **地点展示名**（POI 名或区县名），右侧可提供「清除」或进入选点页改选。

### 3.2 选点交互

与 **发布活动 `location-picker`** 对齐：

- 关键词搜索店铺/地名（高德 Web）。
- 静态地图预览 + POI 列表。
- **使用我的位置**：在选点页内仍可用；确认后作为搜索锚点（非仅恢复 GPS 缓存逻辑，见 §4.2）。

进入方式：`首页点击搜索栏` → `navigateTo` 选点页（带 `from=home` 参数）。

### 3.3 副标题

| 状态 | 文案 |
|------|------|
| 默认（GPS） | `{GPS 城市名} · 今天就能找到人` |
| 已搜索 | `{搜索地展示名} · 今天就能找到人` |

展示名优先 POI `name`，过长可截断；无 POI 名时用 `cityName`（逆地理/列表规则）。

### 3.4 筛选 chips（不变）

保留：**今天 / 明天 / 距离优先 / 全部**。  
仅 **数据源锚点** 从 GPS 改为「搜索锚点（若存在）否则 GPS」。

## 4. 业务规则（已确认）

### 4.1 搜索粒度

- 用户选择 **POI 一条** 即可（须含 **GCJ-02 `lat/lng`**）。
- `cityCode` 由 POI `adcode` 经 `adcodeToListCityCode` 转为列表用地级市码（与 `homeCity.js`、发布选点一致）。

### 4.2 锚点模型

```text
首页活动锚点 = 搜索锚点（若存在） ?? GPS 锚点（resolveHomeCityForActivities）
```

| 存储键（建议） | 含义 | 与现有键关系 |
|----------------|------|----------------|
| `HOME_SEARCH_ANCHOR` | 搜索选中：`lat,lng,cityCode,displayName,address?` | **独立** |
| `HOME_USER_LOCATION` / `HOME_CITY_CODE` / `HOME_CITY_NAME` | GPS 解析缓存 | **不覆盖**；清除搜索后仍可用于恢复 |

**持久化**：搜索锚点写入本地 Storage；杀进程再进首页仍生效，直到清除。

### 4.3 各 chip 下列表逻辑

| Chip | 接口 | 参数来源（锚点 = 搜索 ?? GPS） |
|------|------|--------------------------------|
| 今天 | `GET /activities` | `cityCode` + `dateRange=today`；可选传 `lat/lng` 用于卡片距离展示 |
| 明天 | `GET /activities` | `cityCode` + `dateRange=tomorrow` |
| 全部 | `GET /activities` | `cityCode` + `dateRange=all` |
| 距离优先 | `GET /activities/nearby` | `lat/lng` = 锚点坐标，`cityCode` = 锚点城市，`radiusKm=5`，`sortBy=distance` |

**距离优先**：默认半径 **5km**，圆心为 **搜索点**（非首次授权位置）。卡片「距您 x km」相对锚点。

**今天/明天**：按锚点 `cityCode` 筛同城活动（后端现有区县扩展规则不变）。

### 4.4 清除与恢复

- 首页搜索栏提供 **清除**（或选点页「使用当前定位」在 `from=home` 时语义为：清搜索锚点 + 重新 `resolveHomeCityForActivities` + 返回刷新）。
- 清除后副标题与列表回到 GPS 锚点。

### 4.5 空结果

- 列表为空时保留现有空态；可增加一句弱提示（**可 v0.1 后置**）：「该地暂无活动，试试「全部」或换附近城市」。

### 4.6 范围隔离

| 模块 | 是否使用搜索锚点 |
|------|------------------|
| 首页 `home.vue` | **是** |
| 发现 `discover` / `place-activities` | **否** |
| 发布 `publish` / `location-picker` | **否**（仍写 `PUBLISH_LOCATION_PICK_RESULT`） |
| 城市大群、消息、我的 | **否** |

## 5. 与发现「搜地点」的差异

| 维度 | 发现 · 搜地点 | 首页 · 搜地点（本需求） |
|------|----------------|-------------------------|
| 页面 | 独立 `place-activities` | **仍在首页**，只换锚点 |
| 搜索 | 偏城市/区县文字联想（`/meta/place-suggestions`） | **地图 + POI**（高德，同 `location-picker`） |
| 筛选 | 该页自有 chips | 复用首页 **今天/明天/距离优先/全部** |
| 结果 | 该页独立列表 | 首页活动流刷新 |

## 6. 验收标准

1. 首页头部可见搜索入口；点击进入选点页，选 POI 后返回，副标题与列表更新。
2. 搜索后「今天」「明天」活动属于搜索地 `cityCode` 范围，而非仅 GPS 城市（跨城场景必测，如 GPS 在北京、搜枣庄）。
3. 搜索后「距离优先」以搜索点为中心 5km 排序；卡片距离相对搜索点。
4. 清除搜索或「使用当前定位」后，恢复 GPS 锚点行为与改前一致。
5. 发布页选点、发现页搜地点行为 **无回归**。
6. `HOME_*` GPS 缓存不被搜索写入覆盖。
